# H-EVAL — EEG Sleep-Onset Forecasting Evaluation

**Code companion for:** *Where Does EEG Sleep-Onset Forecasting Skill Arise? A State-Conditioned Evaluation*

> **Status:** private, pre-submission reproduction package (`v0.1.0-paper-review`).
> - It contains only the code and aggregate evidence that support the named paper.
> - It is not the complete research history.
> - It does not propose a new EEG model.
> - It is not an accepted conference version.

## Scientific question
- **The concern.** A pooled forecasting score can improve over a constant even when the improvement accrues mainly on inputs already scored as Stage 1.
- **What this work does:**
  - attributes Brier-score differences to the scored input state;
  - compares EEG forecasts with retrospectively stage-conditioned *diagnostic* references;
  - separates discrimination, probability calibration and warning behaviour.
- **Task.**
  - Data: 30-second, two-channel EEG windows (Fpz-Cz, Pz-Oz) from Sleep-EDF Expanded.
  - Decision points every 30 s from lights-off.
  - Event: the first scored Stage 2 epoch (first N2) within a 300 s horizon.
- **Models:**
  - **Constant:** the training prevalence.
  - **SpecLR-18 / SpecLR-46:** logistic regression on ten log band-power and amplitude features.
  - **RawCNN-46:** a generic multiscale 1D CNN.

The CNN is **not claimed to be a new architecture**. The Stage-only and Stage+time references use retrospectively scored sleep stages and are **not deployable online**; they are diagnostics, not upper bounds.

## Quick start (aggregate-only reproduction; no EEG data needed)
Use an **existing** Python environment that satisfies `requirements-paper.txt`. This repository does not create or modify environments.
```bash
export PYTHON=/path/to/your/existing/python3          # must already have the packages in requirements-paper.txt
"$PYTHON" -m pytest                                    # 5 tests: snapshots, privacy, tables, figures, claims
"$PYTHON" scripts/paper/verify_final_claims_v8r5.py    # 29 numerical manuscript claims vs aggregate snapshots
PYTHON="$PYTHON" bash scripts/paper/build_paper.sh     # regenerate tables+figures, check identity, build the PDF
```
**What these commands verify:**
- `paper/latex/tables_generated.tex` is regenerated byte-identically (Git blob `f4ac863b0130ef5c8c9253d14bbc2e375b550cd9`).
- All 16 figure files are regenerated byte-identically from the snapshots in `results/aggregates/`.

Byte identity of the figure files additionally requires the Liberation Sans font and the package versions listed in `requirements-paper.txt`.

**Interval procedures:**
- Rows 1–3 use the intervals of each original prespecified evaluation (paper Table 1).
- Retrospective rows use a post-hoc re-bootstrap (paper Table 2; 10,000 person-cluster replicates).

**Interpretive limits:**
- The retrospective rows describe heterogeneity. They are not independently confirmed hypotheses: no multiplicity adjustment was applied, and no positive within-state contrast replicated across cohorts.
- `docs/experimental_status.md` lists the status of every result family.

## What is reproducible here
1. **Aggregate-only reproduction (verified).**
   - Tables, figures and 29 numerical claims from the snapshots.
   - Commands above; results in `docs/reproducibility.md`.
2. **Method unit tests (partly runnable without data).**
   - `"$PYTHON" -m pytest scripts/decision/h_eval/<module>/test_*.py`.
   - Most pass on synthetic inputs.
   - Tests that need private local data or excluded artefacts fail; each failure and its cause is listed in `docs/reproducibility.md`.
3. **End-to-end replay from raw EEG: not supported by this package.**
   - It needs the separately downloaded PhysioNet data plus development-repository provenance artefacts that are deliberately excluded here (split rosters, per-window predictions, model manifests and approval records).
   - The original held-out evaluations were one-shot tests and are archived here for inspection, not for re-execution as new tests.

No clean-room reproduction on a second machine has been performed yet.

## Ethical use
This is an evaluation-methodology study, **not** a validated clinical or safety-critical drowsiness alarm. Do not use these results as deployment evidence.
